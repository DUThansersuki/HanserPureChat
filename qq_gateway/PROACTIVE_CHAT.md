# Hanser QQ 主动话题

**2026-10-27：用户要求先关闭主动话题，本机 `gateway.proactive.enabled=false`。以下保留功能说明，当前不会自动发起聊天。**

2026-10-19 · 第一版已接入本项目现有文字链路。本机在原 `user_trial` 上启用，仅面向已有的 1 个指定私聊用户，群聊关闭。新环境示例默认关闭。

## 角色怎样找话题

沿用当前 Hanser Persona 编译器、关系和表达许可、近期表达观察、全量 Style 检索、口癖试用提示以及统一 Responder。主动触发的任务类型已经确定，不额外调用 Planner 分类；生成正文通常只需一次现有回复模型调用。

选题按以下顺序进行：

1. 最近 72 小时的真实用户消息中，明确表达正在做、准备做的事项，可作为进度话题。完成、取消、否决、历史叙述、引用或假设中的事项不采纳；近期已经问过的同一来源先避开。
2. 当前用户有效的正向兴趣 Memory，例如游戏、听歌、电影或绘画，作为轻量话题。保留 Memory 和原始消息 ID；不读取其他用户或群聊身份的私聊记忆。
3. 没有合适线索时，在近况、音乐、小开心等日常方向中轮换，不要求角色必须编出一件自己的日常事件。

这是小范围可解释的规则选题，复杂或不明确的事项会落到普通闲聊。选题资料以数据形式交给模型，约束其询问仍未知的进展，不预设事情仍在做、已经成功或用户此刻的状态。生成提示要求自然好奇、有自己的语气，避免客服问卷、催进度、固定昵称、堆口癖和“怎么不理我”式催回复；不虚构“我刚下班/吃完”“一直等你”或监视用户在线的经历。

真实预览复现了“我这边歌单循环到腻了”的无依据当前自述，现增加针对这类自述的检查，保留“我想听你说说/我有点好奇”等对话姿态。命中后用同一个 Responder 最多重写一次，并重新计算完整上下文预算；仍不合格则停止该主动任务，不发送伪装成正常聊天的兜底。被拒输出和调用次数保留在本机账本，旧缓存草稿在发送前也执行该检查。

## 当前频率

| 项目 | 本机配置 |
| --- | --- |
| 目标 | 现有指定私聊，必须在明确的 `private_users` 中 |
| 空闲等待 | 最后一条用户消息之后 4 小时，再随机延迟 0–30 分钟 |
| 允许时段 | 09:00–22:30，Asia/Shanghai |
| 每日上限 | 每个私聊最多安排 1 次；生成失败不会不断新建任务 |
| 未回应 | 发出第一段并得到确认后暂停主动聊天，收到新输入再恢复 |
| 迟到/离线 | 超过 10 分钟的旧时机跳过并重新等待，不补发过期问候 |
| 忙碌/休息 | “我现在忙/晚点再聊”等暂停 6 小时；“晚安/先睡了”暂停到次日 9 点 |

首次为既有会话开启时，从启用时重新等待一段空闲时间，不立即向历史联系人发消息。没有实际私聊过的用户不会由配置凭空建对话。QQ 必须明确在线才调度生成；离线、未知在线状态和勿扰时段不调用模型安排主动话题。

## 关闭、恢复与预览

可直接私聊说：

- `不要主动找我` / `不要主动给我发消息`：持久关闭主动聊天，普通聊天仍可使用。
- `可以主动找我` / `开启主动聊天`：恢复当前用户的主动开关，仍受频率、时间窗和已发送额度限制。
- `晚安，我先睡了` / `我现在忙，晚点再聊`：进入对应休息/忙碌暂停。

只有直接用户消息控制状态，引用或举例不作为操作。QQ 回复对开关操作使用已落库事件的真实回执，避免让模型否认或编造产品能力。全局关闭时不会因私聊指令越过管理员配置。

不发 QQ 的实际模型预览，在 `qq_gateway` 中运行：

```powershell
.\.venv\Scripts\python.exe -m hanser_qq proactive-preview
```

本机只有一个指定私聊，命令自动使用该已有会话；多目标时显式提供 `--conversation-id 'qq:dm:机器人号:用户号'`。输出含正文、分段、选题类型、Persona、口癖版本及来源 ID。预览会产生实际模型费用，并保存草稿；不写聊天消息或 Memory，不能通过发送回执接口把预览伪装成已投递。

`status` 的 `proactive` 显示开关、窗口、空闲时间、未回应/退出数量、任务状态和待同步历史回执数量，不输出用户正文或号码。全局参数在 `config.yml` 的 `gateway.proactive`，变更后重启 Hanser：

```yaml
proactive:
  enabled: true
  idle_seconds: 14400
  jitter_seconds: 1800
  daily_limit: 1
  start_hour: 9
  end_hour: 22.5
  poll_seconds: 60
  expiry_seconds: 600
  context_hours: 72
```

此配置块位于 `gateway` 之下。`private_users` 留空不会开启对所有联系人的主动发送。

## 对话、记忆与发送账本

主动触发走独立的系统事件接口，不伪造用户发言，不调用 PostTurn 为用户提取事实或增长熟悉度。使用现有 ContextBuilder 在最终 system 角色下计算预算和提示版本，Persona、Style、权限和口癖来源可以回查。

草稿及生成结果先写入 QQ 独立数据库。发送使用原会话队列与逐段确认：只有 QQ 确认发出的前缀进入一条 assistant 历史，后续确认扩展同一消息；未知、失败或未发送部分不会冒称已对话。回执同步临时失败时保留已确认发送记录，恢复后同步，不重发确认前缀。来源 Memory 被删除或会话出现新用户消息，会在发送前重新检查并取消过时话题。

用户发来新消息后，取消待发候选和主动生成，让普通聊天先处理；剩余主动段停止，发送中的单条继续按实际回执记账。正常用户轮次的既有“不取消已开始生成”规则不变。结果不明的发送不自动重试，仍保留原维护处理能力。

两个进程仍由 `hanser_qq run` 管理，调度在现有 Gateway 内运行，无需新增常驻程序、AstrBot 框架或 Codex 自动任务。设计参考前一轮对 [Pancakes 主动聊天](https://github.com/Pancakes-Labs/astrbot_plugin_proactive_chat) 和 [private_companion](https://github.com/menglimi/astrbot_plugin_private_companion) 的调研；代码按本项目的 Persona、数据库和发送协议重新实现，没有复制第三方代码。
